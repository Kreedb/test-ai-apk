# #63 真机反馈修复与复测

## 预览与监控根因

- 旧相机只请求 640×480，且显示模型预处理后的方形小图。现在请求 1280×960，通过原有坐标映射直接绘制原始像素；模型输入大小不再决定预览清晰度，首帧日志报告设备实际返回的尺寸。
- 监控用空图层占位，下一帧到来时来源校验把它从监控集合移除，文字落入底部报告。现在按 `MONITOR` 能力路由文字，图像层仍检查严格同源，默认采样间隔降至 250 ms。

## 反馈对应

| 反馈 | 交付 |

| 2 预览清晰度 | 请求更高源分辨率，直接显示相机原始像素 |

## 标签核对

固定目录文件实际内含 MobileNet `labels.txt`（1001 类）、SSD `labelmap.txt`（90 类）、DeepLab `labelmap.txt`（21 类）、YAMNet `yamnet_label_list.txt`（521 类）。YAMNet 是逐行标签文本，`Child speech, kid speaking` 中的逗号属于类别名称，不应按 CSV 拆开。标签与权重共用已校验的文件，无需另外维护不匹配的类别清单。

已使用 Gradle 编译后的实际 Kotlin `ModelLabels.read` 读取这四个下载文件，类别数全部匹配；YAMNet 静音输入最高分索引 494 对应 `Silence`，验证标签索引未偏移。

Android [ZipFile 源码](https://android.googlesource.com/platform/libcore/+/refs/heads/main/ojluni/src/main/java/java/util/zip/ZipFile.java) 额外要求文件第 0 字节是 ZIP 本地头或空 ZIP 结束头；TFLite 的 FlatBuffer 开头不满足它，因而报 `Entry at offset zero has invalid LFH signature 1c`。这不是模型损坏。目录里的实际中央目录偏移均为绝对偏移；读取器应解析尾部 ZIP，而不是直接把整个 `.tflite` 交给 Android `ZipFile`。

宿主在录音授权/撤权时更新插件代次，声音插件原来只处理启动与配置，未接收新权限事件，导致已加载模型对应旧代次。现在授权后按新代次加载，撤权释放窗口与模型，再授权可重启；回归使用真实插件和宿主，在文件读取边界停止，验证两次授权均触发新加载。

## 平台依据

- [CameraX ResolutionStrategy](https://developer.android.com/reference/androidx/camera/core/resolutionselector/ResolutionStrategy)：请求尺寸并非设备保证；`FALLBACK_RULE_CLOSEST_HIGHER_THEN_LOWER` 优先选择接近的更高尺寸，无可用项时再回退更低尺寸。
- [UtteranceProgressListener](https://developer.android.com/reference/android/speech/tts/UtteranceProgressListener)：回调可能来自多线程；`onDone` 表示可听音频已经播放完毕，`onStop` 表示停止或队列清空，不能把 `speak()` 返回成功当作播放完成。

## 设备复测

1. 更新安装，确认原有导入模型、配置、开关和训练存档仍可用。
2. 关闭全部插件：保留清晰预览，无姿态状态文字、骨架或监控输出；分别只开姿态增强、只开自定义模型，确认结果归属与模型开关一致。
3. 同开姿态增强和系统监控：帧率始终在右上角，NPU 行可见；将刷新间隔设为 250 ms 与 1000 ms 核对变化，底部只出现明确的诊断或其它插件结果。
4. 分别配置 YOLO26n 与 YOLO11n，核对配置项、输出布局、保存恢复；打开多个模型后检查日志逐个加载，关闭一个后只停止它。
5. 超分：用文字/斜线覆盖画面四角，按住预览等待整幅处理完成；所有区域均有对应结果。处理中松手、滑出、多指、切页或后台，必须恢复最新实时预览，迟到结果不得覆盖。
6. 动作观察按界面提示测试全身/遮挡/出画；物品识别查看真实标签；物体检测核对数量、类别和框位置；分割核对类别图例、覆盖面积与背景，移动相机时不留旧蒙版。
7. 声音识别首次下载与已有缓存升级均应成功加载标签；录音拒绝、撤权、后台后必须停用采集，预览仍工作。
8. TTS 朗读完成后状态恢复；切换已安装引擎、缺失语音包、停止、连续朗读及后台，状态和实际发声一致。
9. 设备端学习按指引命名、添加样本、训练、重新进入与相机识别；验证旧存档及训练失败不会破坏已有模型。
10. 设置点击应用自检，核对逐项结果和日志，包含未下载/不支持的明确原因；完成后分享日志用于定位失败阶段。

## 验证边界

本次运行环境 `adb devices -l` 无设备，`/dev/kvm` 无读写权限；不把 JVM 或主机 CPU 推理作为手机 CameraX、Bitmap、TTS 引擎、麦克风和 GPU/NPU 的执行证据。

当前 JVM 回归：**300 tests，0 failures，0 errors，1 skipped**（既有可选大文件网络冒烟）。覆盖旧模型开关迁移、模型失败隔离、标签 CRC/偏移、TTS 乱序回调、权限重新授权、完整抬臂周期、分割 logits、整幅分块、旧/新训练存档、只读分类头自检与全部模型枚举。

JDK 21 执行 `assembleDebug assembleRelease lintDebug testDebugUnitTest --build-cache --parallel --console=plain` 成功，lint **0 errors / 20 warnings / 1 hint**。警告为版本更新、固定方向、可分配存储建议及 KTX 风格建议。两个 ABI 的 Release 签名校验成功，APK 均只内置 YOLO26n；arm64-v8a 90,021,282 字节、x86_64 19,372,340 字节。

主机使用 `ai-edge-litert 2.3.0` 对内置 YOLO26n 做零输入 CPU 推理，得到有限输出 `[1,56,8400]`；Android 打包运行时版本为 2.3.2，两者不等同。

独立下载并核对 7 个场景模型的大小和 SHA-256，CPU 冒烟输入的全部输出均为有限数值：ESRGAN `[1,200,200,3]`、MoveNet `[1,1,17,3]`、MobileNet `[1,1001]`、SSD 四输出、DeepLab `[1,257,257,21]`、YAMNet `[1,521]`，设备端学习的 `load` 签名 `[1,62720]`。这验证模型文件与算子路径，不代表真实图像精度或手机性能。

Google Coral 固定提交的 `grace_hopper.bmp` 语义冒烟：按目录的 mean/std=127.5 预处理后，MobileNet 首项为 `military uniform`（0.867），SSD 输出含 `person` 与 `tie`，DeepLab 主体为 `person`（约 61.9%）。用于核对标签索引与基础数值范围，不是准确率评测集。

独立代码审计的两项发现已处理：固定视觉插件直接使用校验后的场景缓存与自身契约，不再解析用户的通用模型配置；自定义模型多行输出按 240 字限制分行，超过 8 行显式提示裁剪。复审未发现新的可证问题。
